# Private History Read Authority

Application PARTIAL_NOT_COMPLETE. This is a bounded retained FastAPI REST history-read correction, not full private-session security or hosted acceptance.

The previous history endpoint used a service-role repository query with workspace/session filters only. Empty results or caught storage errors then restored workspace-keyed process memory. Another workspace member could request a known private session and reach history without owner/participant authority. Source reproduction demonstrates this path; no active hosted FastAPI exposure is inferred.

The endpoint now passes the already-validated inbound Supabase JWT through a non-repr request-local field. A dedicated RPC transport supplies the public API key and that JWT, never the service-role helper or its credential fallback. The read_private_history RPC checks auth.uid and the existing private-conversation predicate against current membership, live sessions, owner, explicit participants and legacy visibility in the same stable statement snapshot as selection. Response validation binds canonical workspace/session UUIDs and the bounded result length. No preflight privileged read followed by an unfenced message read was added.

Malformed/absent credentials, missing configuration, malformed or foreign-scope receipts and transport failure stop with static503. Private exceptions are not rendered or logged; cancellation propagates. An unauthorized/empty response stays empty, without an existence oracle or memory fallback. Explicit no-Authorization local/demo behavior remains available; supplied bearer requests cannot downgrade to demo. JWT signature/audience validation, roles, RLS policies, session creation and mutation semantics are unchanged.
